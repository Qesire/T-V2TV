# 04 · 最小证据树、实验设计与推进条件

核心目标：以最少重复训练区分 **视觉读取、语义对齐、可控制性、文字重建的独立贡献**。本文件规定实验的因果比较；未运行任何视频生成、训练或评分。生成视频将保留供人工检查。

## 研究门槛

| 门槛 | 研究问题 | 最小对照 | 满足后下一步 |
|---|---|---|---|
| E0 静态算子 | 原始 Wan 和新增模块的 shape、frame index、noise clock、零初始化与反传正确吗？ | 受控张量与有限差分／autograd 检查 | E1 |
| E1 R：读到视觉动作了吗？ | 当被遮蔽动作词不变，真实视频变化是否改变恢复器的相关预测？ | 正确视频 / 相反动作 / 帧逆序 / 错配视频 / 纯文字；相同 mask | E2 |
| E2 W：写得动吗？ | 在有效的去噪步骤上，明确的时间/动作干预能否改变最终视频？ | 无写入 / 全局 Value / 显式时间路由 / 有限 oracle | E3 |
| E3 G：视频增益来自哪里？ | 加文字重建与动态反馈后，事件与时序是否真改善？ | 同一训练数据、同样 adapter、相同 seeds 和推理预算的逐项对照 | 扩大数据与鲁棒性验证 |

### E0：无需视频训练的算子单元测试

- Wan 原始代码跑单次 forward；冻结所有模型权重、新增残差零初始化时，与同精度同 seed 的原生输出逐值一致（报告 max/mean error；不预设错误的 bitwise FP16 等价）。
- 构造两帧、两事件：`A_{f,e}` 对帧调换应随之交换；无序全局 pooling 不应被误认为能识别顺序。
- 梯度必须从 `\mathcal L_{\rm video}` 到 `VideoWrite` 及 `TextRestore` 可达；冻结的 Wan 权重无参数梯度。不要因推理代码里 `torch.no_grad()` 而复制其训练图。
- 各自时间进度 0/1 在“本文抽象”与 Wan scheduler／MDLM 噪声率之间要建立数值映射表，并测试两端。
- mask 必须基于文字模型 tokenizer 的真实 span，检查 subword 边界、长度和空事件输入。

### E1：文字重建是否有真实视频语义

对每条有明确动作关系的 prompt 构造 `(c,z_s,V^+,V^-,V^{\rm reverse})`：

- `V^+`：视觉内容符合目标动作／顺序；
- `V^-`：主体/背景尽可能匹配，但动作方向、对象或次序不同；
- `V^{\rm reverse}`：对可逆序的案例改变时间顺序（实际视频逆放可能带来物理异常，只用于机制 probe）；
- `z_s`：遮住目标动作／关系的同一组 token，不能为不同视频重新采样 mask。

比较 `\log p_\phi(c_{\rm masked}\mid z_s,R(V^+))` 与错误视频的对应值；同时保留完整词概率分布、错误答案的 logit 差和视觉状态对文本状态的归因。对真实视频 `x_t` 以多个视频噪声水平重复；也在**模型生成轨迹**的 `\hat x_t` 上测，避免 teacher-forcing 假阳性。

衡量的是被遮蔽语义的差异，不只是整句 token 恢复率。若遮住的词仅凭剩余文字即可唯一恢复，记为语言先验案例，不把它作为视觉读取证据。

**推进规则**：如恢复器不能区分相反动作，先修读取位置／时间表示与 mask 任务；不推进视频反馈训练。

### E2：确认视频骨干在何处可被语义驱动

使用原生 Wan2.1 的固定 seed 和相同 prompt 先生成 baseline。只对有限层、有限步改变写入；在少量复杂事件 prompt 上保留视频，而非仅看 `\|\Delta v\|`。

- **Base**：无附加写入；
- **Value-only**：共享文本值向量的扰动；
- **Time-routed residual**：按事件-帧映射写入；
- **Oracle routing**：给定人工指定的正确事件时段测试接口上界；此组不作为无额外信息的最终性能基线。

测试读出：
1. 改动是否到达预期时间区域；
2. 目标动作是否真的完成（人工视频复核）；
3. 对主体、外观、帧间稳定性是否造成退化；
4. 需要在哪些采样进度注入才能对最终视频生效。

仅有速度预测响应或注意力图变动不算通过。若 oracle 也无法推动最终事件，优先修改写入层、位置或表示，不以训练文字扩散作为补救。

### E3：有限后训练的必要对照

| Arm | 文字中间态 | 文字重建监督 | 视频接口 | 区分什么 |
|---|---|---|---|---|
| A | 无 | 无 | 原 Wan | 原始下限 |
| B | 固定或单次计算的语义表示 | 无/与 C 匹配的辅助监督单独报告 | 与 D 相同 | 表示与额外参数本身是否已够 |
| C | 动态去噪中间态 | 无（只视频目标） | 与 D 相同 | 动态结构自身的作用 |
| D | 动态去噪中间态 | **有，恢复原 prompt** | 与 C 相同 | 文字重建损失的独立贡献 |
| E | 与 D 相同 | 同 D | 增加可训练事件时间路由 | 显式时间对齐是否再带来收益 |

优先 B/C/D，再看 E；E2 没有时序可控制证据时不投入 E。各组匹配数据划分、训练视频数、优化步骤、随机种子与推理设置；记录可训练参数、训练 GPU·小时、峰值显存、每视频 wall-clock／denoiser forward 次数。若计算不匹配，应分别给出质量—计算 Pareto 比较，而非直接宣称“更好”。

## 数据与统计单位

首批人工可核验 prompt 以**短、连续单镜头、2–3 个清晰事件**为主，包括：（a）先后动作；（b）同一对象的抓握—移动—释放；（c）主体与目标对象绑定；（d）关键状态持续与转变。不要把单纯动作字幕分类当成视频生成质量。

- **统计独立单位**是 prompt／原始视频来源。对同一个 prompt 的多 seed 是相关重复，不应算成独立 prompt 数。
- Baseline 与方法使用相同 prompt、seed、分辨率、帧数、调度器和 CFG 设置，产生**配对视频**。
- 自动评分提供辅助代理（帧级 VLM 判定、事件顺序和视频一致性等），优先保留可复核的原始预测；人工视频对照采取盲法、随机展示顺序，并区分“事件成功”与“视觉质量”。
- 汇总用 prompt 为聚类单位的配对差值和不确定区间；样本少时先报告原始案例和分布，避免单一均分掩盖相反效果。
- 先冻结评测 prompt 和评价规范，再训练；观察结果后新增的 prompt/指标登记为探索性，不倒填到原先的验证集中。

## 为什么首先测两个窗口

用 `R(t)` 表示生成中视频语义可被读出的程度，`W(t)` 表示该时刻注入后还能改变最终目标事件的能力。有效的闭环需要两者在**某个去噪进度区间同时非零且方向正确**。

实验上先获取单独的 `R(t)` 曲线（文字遮蔽诊断）和 `W(t)` 曲线（给定语义干预的最终视频变化），再选择有交集的步骤训练联合反馈。不要先验地把“视频去噪进度=文字去噪进度”作为唯一调度；也不要因为某论文某个案例在前 5 步形成轨迹，就推广所有运动在相同步数确定。

## 实验资产约定（实施时创建，当前未产生）

```text
experiments/
  prompt_sets/              # c, event spans, type, source_id, split；不混训练与验证
  configs/                   # 原生 Wan / adapter / text denoiser / sampler
  runs/<run_id>/
    manifest.json            # base_sha, source_shas, checkpoint, code revision, data version
    raw_scores.jsonl         # 每 prompt、seed、视频维度及人工标签
    recon_traces.jsonl       # mask, 每文字步 token 概率、R(t)、s(t)
    align_traces/            # A[f,e]、相关视觉时间位置索引
    videos/                  # base/method 成对 mp4，供人工检查
    runtime.json             # GPU、显存、前向次数、时长
```

视频与大权重不提交 Git；只把足以溯源的 manifest、脚本、摘要和必要的小型诊断数据纳入仓库。实际运行后才能给出完成状态和指标。

## 停止或转向判据

- R 持续失败：停止联合训练，先修读取条件或重新定义文字腐化任务。
- W 在 oracle 语义／时间路由下仍无预期最终视频改变：停止文字去噪训练，先换控制接口。
- R/W 有证据，D 相比 C 无可重复视频收益：文字重建可能只是辅助任务负担；保留其他结果，不以文字准确率代替收益。
- D 不优于 B，且成本更高：原文恢复中间态有可能有用，但没有证据说明“**持续去噪**”是必要机制。
- E 改善但 D 不改善：贡献更可能来自时间对齐控制，后续论文叙述应据此调整。
